# Mintland PoC на Mint — правила сосуществования с Dark Mode

Эксперименты с живыми обоями (слой под иконками) должны жить рядом с апплетом
**Dark Mode (darkMode@linuxedo.com)** и не ломать его. Здесь — жёсткий контракт.

## Что принадлежит апплету Dark Mode — НЕ ТРОГАТЬ

Апплет при переключении тёмный/светлый пишет в dconf:

| Схема / ключ | Что это |
|---|---|
| `org.x.apps.portal color-scheme` | предпочтительная цветовая схема |
| `org.cinnamon.desktop.wm.preferences theme` | тема рамок окон |
| `org.cinnamon.desktop.interface gtk-theme` | GTK-тема |
| `org.cinnamon.desktop.interface icon-theme` | иконки |
| `org.cinnamon.theme name` | тема Cinnamon |
| `org.cinnamon.desktop.background picture-uri` | **обои** (свои наборы для light/dark) |

Правило для всех скриптов эксперимента: **ни одного вызова `gsettings`/`dconf`**.
Слой обоев не читает и не пишет системные настройки вообще.

## Известное (не ломающее) пересечение

Апплет Dark Mode меняет обои. Наш слой рисуется ПОВЕРХ системных обоев, поэтому
пока эксперимент включён, смена обоев при переключении тёмного/светлого режима
будет невидима — она произойдёт «под» слоем. Это ожидаемо и откатывается
выключением слоя (`wall-off.sh`). Никакой деградации схемы переключения нет.

## Чего скрипты не делают (kill-политика)

- не убивают и не перезапускают `cinnamon`, `muffin`, `csd-*`;
- не трогают чужие окна и процессы;
- убивают только собственные процессы: группу, записанную в `run/wall.pid`
  (`setsid`), плюс фолбэк по уникальному пути `mintland/themehost.py`
  и по `deskwall --create`;
- `nemo-desktop` — единственное намеренное исключение: `wall-off.sh`
  перезапускает его **после** снятия слоя. Это возвращает Nemo роль
  рабочего стола и не затрагивает Dark Mode: позиции иконок хранятся
  в gvfs-метаданных, а тема/обои — в dconf, который мы не читаем и не пишем.

## Ярлыки

| Ярлык на рабочем столе | Действие |
|---|---|
| `Mintland-вкл.desktop` | `wall-on.sh` — запустить текущий эксперимент (`experiment.sh`) |
| `Mintland-выкл.desktop` | `wall-off.sh` — остановить, проверить чистоту |
| `Mintland-статус.desktop` | `wall-status.sh` — что сейчас работает |

## Итоги Шага 1 (12.11.2026) — слой под иконками работает

Проверено на живой машине (Mint 21.x, Cinnamon/Muffin, X11, 2560×1440):

| Попытка | Результат |
|---|---|
| `xwinwrap -ov` (в т.ч. `-argb`, `-fdt`, `-ovr`) | ❌ BadMatch: парентится в **overlay-окно XComposite** (окно без свойств, глубина/визуал не совпадают) |
| override-redirect окно в root (`deskwall` v1) | ❌ Muffin **поднимает OR-окно наверх** — перекрыло весь экран, XLowerWindow/CWSibling не держатся |
| **управляемое окно (не OR) + `_NET_WM_WINDOW_TYPE_DESKTOP` + BELOW/SKIP_TASKBAR/SKIP_PAGER + input=False (WM_HINTS) + XShape(input, empty) + watchdog CWSibling-Below к nemo-desktop** | ✅ видео под иконками, панель на месте, окно не в альт-табе |

Инструмент: `deskwall.c` → `bin/deskwall` (форкает mpv, живёт столько же,
каждые 2 с переставляет своё окно строго ниже окна `nemo-desktop`).
Вывод для всех следующих шагов: **никаких override-redirect окон — только
управляемое окно с типом DESKTOP**.

Не проверено человеком: кликабельность иконок (по архитектуре должно
работать: nemo-desktop выше, input-форма у нас пустая).

## Итоги: рабочий прототип (13.11.2026)

Проверено на живой машине (Mint 21.x, Cinnamon/Muffin, X11, 2560×1440):

| Подход | Результат |
|---|---|
| DESKTOP-окно + `keep_below`, `nemo-desktop` запущен раньше | ✅ сцена под иконками, иконки видны и кликабельны |
| `deskwall -u` после старта слоя | ✅ поднимает nemo поверх сцены, иконки не теряются |
| `wall-off.sh` → `wall-on.sh` повторно | ✅ сцена и иконки возвращаются |
| Контейнер `deskwall --create` + reparent WebKit | ⚠️ сцена рисуется, но nemo теряет роль рабочего стола → иконок нет; отклонён |
| NORMAL-окно под иконками | ❌ всегда выше DESKTOP-слоя, иконки скрыты |
| XShape-«прорези» под иконки | ❌ отклонено: хрупко и не нужно при правильном стеке |

Ключевое условие: **`nemo-desktop` должен быть запущен до создания слоя**.
Если слой уже существует, Nemo пишет `Desktop already managed by another
application, skipping desktop setup` и не рисует иконки. Поэтому
`wall-off.sh` всегда перезапускает Nemo после снятия слоя.

## Структура

```
experiment.sh   — сам эксперимент (меняем его, ярлыки не трогаем)
wall-on.sh      — обвязка запуска: проверки окружения, PID-файл, deskwall -u
wall-off.sh     — обвязка остановки: kill группы, перезапуск nemo-desktop
wall-status.sh  — текущее состояние
run/            — wall.pid, wall.log (gitignore)
```
