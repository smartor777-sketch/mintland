# Темы Mintland: как устроены и как добавить новую

> **Документ:** техническое описание контракта темы и порядка добавления новой.
> **Дата:** 13.11.2026.
> **Область:** `prototype/`, `switcher.py`, `themehost.py`, `tools/`.
> **Аудитория:** тот, кто добавляет тему — свою или портированную.
> **Пути:** все пути в документе — от корня репозитория, не от `docs/`.

---

## 0. Коротко

Тема Mintland — **не картинка и не набор видеофайлов**. Это **HTML-страница со
сценой**, которая каждый кадр рисует себя сама и принимает от хоста
прямоугольники иконок, параметры и команду «пауза». Фон и PNG-ассеты — лишь
материал, которым эта страница пользуется.

Причина простая: сцена **подстраивается под иконки**. Берег обтекает их
контуры, облака собираются вокруг, ореол подсвечивает. Статичный фон так не
умеет — он не знает, где стоят иконки и какого они размера.

Минимальный комплект новой темы:

```
prototype/<тема>.html          ← сцена: рисует кадр, слушает протокол хостa
prototype/themes.json          ← запись темы (id, имя, страница, параметры)
switcher.py                    ← русские подписи, порядок карточек, превью
docs/theme-<тема>.gif          ← анимированное превью (необязательно, но принято)
```

Ассеты (`prototype/assets/*.png`) — только если сцена их использует.

|---|---|---|
| Пляж | `prototype/flat.html` | WebGL2-шейдер: береговая линия строится по иконкам, волны, пальмы, каяки, чайки |

## 2. Контракт страницы

### 2.1. Как хост открывает тему

`themehost.py` загружает страницу так:

```text
file:///…/prototype/<тема>.html?wallpaper=1
```

и **до** загрузки страницы вставляет шим, который подменяет API WebView2
(Deskland был написан под Windows, страницы ждут `window.chrome.webview`):

```js
window.chrome.webview.addEventListener('message', cb);  // входящие сообщения
window.chrome.webview.postMessage('ready');             // исходящие
```

Шим определён в `themehost.py` (`SHIM_JS`). Менять его не нужно — нужно
пользоваться им.

### 2.2. Сообщения: хост → страница

| Сообщение | Поля | Смысл |
|---|---|---|
| `icons` | `vis: bool`, `r: [[l,t,r,b], …]` | Прямоугольники иконок в **физических** пикселях. Приходят раз в 2 с, а также сразу после загрузки и переключения темы |
| `settings` | `v: {ключ: значение}` | Параметры темы. Частичное обновление, не полный набор |
| `reset` | `v: {…}` | Сброс к значениям по умолчанию |
| `pause` | `v: bool` | `true` — на экране развёрнутое или полноэкранное окно, анимацию надо остановить |

### 2.3. Сообщения: страница → хост

Одно: строка `ready`, когда страница готова принимать сообщения. Хост по ней
запускает опрос иконок и паузы.

### 2.4. Обязанности страницы

1. Отправить `ready` **после** того, как сцена готова рисовать.
2. Принять `icons` и учесть прямоугольники в отрисовке.
3. Принять `settings` и применить только те ключи, которые знает.
4. **Уважать `pause`**: на паузе не планировать следующий кадр. Это не
   пожелание — без этого сцена будет жечь ядро под полноэкранным видео.
5. Ограничивать FPS (в существующих темах — 30 fps, флаг `cap30`).

### 2.5. Минимальная рабочая тема

Такой файл уже запускается, включается и выключается, но ещё не знает про
иконки:

```html
<!DOCTYPE html>
<html lang="ru">
<head><meta charset="utf-8">
<style>
  html, body { margin: 0; height: 100%; overflow: hidden; background: #06101f; }
  #art { position: fixed; inset: 0; width: 100vw; height: 100vh; }
</style>
</head>
<body>
<canvas id="art"></canvas>
<script>
(function () {
  'use strict';
  var cv = document.getElementById('art');
  var ctx = cv.getContext('2d', { alpha: false });
  var P = { glow: 60, cap30: true };
  var icons = [], paused = false, last = 0;

  function resize() {
    var dpr = Math.min(window.devicePixelRatio || 1, 2);
    cv.width = Math.round(innerWidth * dpr);
    cv.height = Math.round(innerHeight * dpr);
    cv.style.width = innerWidth + 'px';
    cv.style.height = innerHeight + 'px';
    ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
  }

  function render(t) {
    ctx.fillStyle = '#06101f';
    ctx.fillRect(0, 0, innerWidth, innerHeight);
    var k = window.devicePixelRatio || 1;
    for (var i = 0; i < icons.length; i++) {          // ореол вокруг иконки
      var r = icons[i];
      var cx = (r[0] + r[2]) / 2 / k, cy = (r[1] + r[3]) / 2 / k;
      var g = ctx.createRadialGradient(cx, cy, 0, cx, cy, P.glow);
      g.addColorStop(0, 'rgba(140,200,255,0.35)');
      g.addColorStop(1, 'rgba(140,200,255,0)');
      ctx.fillStyle = g;
      ctx.beginPath(); ctx.arc(cx, cy, P.glow, 0, Math.PI * 2); ctx.fill();
    }
  }

  function frame(now) {
    if (paused) { last = 0; return; }                 // на паузе кадр не планируем
    requestAnimationFrame(frame);
    if (P.cap30 && now - last < 31) return;
    last = now;
    render(now);
  }

  function handle(m) {
    if (!m || !m.t) return;
    if (m.t === 'pause') { paused = !!m.v; if (!paused) requestAnimationFrame(frame); return; }
    if (m.t === 'settings') { for (var k in m.v) if (k in P && typeof m.v[k] === typeof P[k]) P[k] = m.v[k]; return; }
    if (m.t !== 'icons') return;
    icons = m.vis ? (m.r || []) : [];
    render(performance.now());
  }

  resize();
  addEventListener('resize', function () { resize(); render(performance.now()); });
  render(performance.now());
  requestAnimationFrame(frame);

  var host = window.chrome && window.chrome.webview;
  if (host) {
    host.addEventListener('message', function (ev) { handle(JSON.parse(ev.data)); });
    host.postMessage('ready');
  }
})();
</script>
</body>
</html>
```

## 3. Как сцена использует иконки

Хост присылает **физические** пиксели (логические × `scale`). Страница делит
их на `window.devicePixelRatio` и получает CSS-пиксели:

```js
const k = window.devicePixelRatio || 1;
icons = m.r.map(([l, t, r, b]) => ({
  x: l / k, y: t / k, w: (r - l) / k, h: (b - t) / k
}));
```

Дальше есть три уровня сложности:

| Уровень | Что делает сцена | Пример | Стоимость |
|---|---|---|---|
| 1 | Ничего: просто фон | минимальная тема выше | часы |
| 2 | Ореол/пятно/тень под каждой иконкой | `night.html` | 1–2 дня |
| 3 | Поле расстояний до иконок, по нему строится рельеф | `flat.html`, `meadow.html` | 1–2 недели |

Третий уровень — это когда берег «обтекает» иконки, а не просто подсвечивает
их. В `flat.html` для этого считается карта расстояний (гауссовы «метаболы» +
шум), по ней шейдер рисует воду, песок и пену.

## 4. Запись в `themes.json`

Файл лежит в `prototype/themes.json` и исторически пришёл из Deskland, поэтому
имена и описания в нём китайские — русские живут в `switcher.py`.

```json
{
  "id": "night",
  "adaptive": true,
  "name": "Ночь",
  "desc": "Звёздное небо, полярное сияние и туман; вокруг иконок — мягкое свечение",
  "page": "night.html",
  "status": "ready",
  "product": "free",
  "thumb": "url(thumbs/night.webp) center / cover no-repeat, linear-gradient(...)",
  "thumbSource": "custom",
  "groups": [
    {
      "name": "Иконки",
      "params": [
        { "key": "halo", "label": "Свечение вокруг иконок",
          "hint": "мягкий ореол, чтобы иконки читались на тёмном небе",
          "min": 40, "max": 200, "step": 1, "default": 96, "unit": "px" }
      ]
    }
  ]
}
```

Правила:

- **`status: "ready"` + `page`** — без этого пара «тема не появится в списке».
  Остальные 11 записей имеют `status: "locked"`.
- **`groups[].params[]`** — из них `switcher.py` строит ползунки и
  переключатели. Ключ `key` должен совпадать с ключом в объекте `P` на
  странице.
- **Тип значения важен.** Страница применяет параметр только если
  `typeof v[k] === typeof P[k]`. Число `1` — это число, а не `true`; `0/1`
  для переключателя, а не `false/true`.
- **Переключатель** — параметр с `options` из двух строк и `default: 0|1`.
  `switcher.py` покажет `Gtk.Switch`.
- **`format`**: `"percent"` (0..1 → «70%»), `"times"` (→ «×0.65»).
- **`thumb`** — запасная миниатюра для `themes.json`; в самом приложении
  используется GIF из `switcher.py`.

## 5. Регистрация в `switcher.py`

Шесть словарей. Если что-то не заполнить, тема всё равно появится, но с
техническими подписями и китайским описанием.

| Словарь | Что задаёт | Если пропустить |
|---|---|---|
| `THEME_INFO` | русское имя, описание, путь к GIF | в карточке будет `id` и пустое описание |
| `GROUP_LABELS` | русские заголовки групп | заголовки будут «Параметры» |
| `PARAM_LABELS` | русские подписи параметров | подписи будут техническими ключами (`halo`) |
| `THEME_ORDER` | порядок карточек | тема уедет в конец (код `99`) |
| `UNIT_LABELS` | единицы измерения | единица берётся из `themes.json`, китайская отбрасывается |
| `DEFAULT_OVERRIDES` | свои значения по умолчанию | берутся из `themes.json` (у Beach там дороже по CPU) |

Пример для ночной темы:

```python
THEME_INFO = {
    # …
    "night": {
        "name": "Ночь",
        "desc": "Звёздное небо, полярное сияние и туман; иконки в мягком ореоле.",
        "thumb": "docs/theme-night.gif",
    },
}

GROUP_LABELS = {"night": ["Иконки", "Небо", "Туман"]}
PARAM_LABELS = {"night": {"halo": "Свечение вокруг иконок", "aurora": "Полярное сияние"}}
THEME_ORDER = {"beach": 0, "meadow": 1, "night": 2}
UNIT_LABELS = {"night": {"halo": "px", "shoot": "шт"}}
```

## 6. Превью

Карточка темы показывает **анимированный GIF** 250×141 из `docs/theme-<id>.gif`.
Порядок поиска в `switcher.py`:

1. `docs/theme-<id>.gif` — анимированное превью;
2. `prototype/thumbs/<id>.webp` — статичная миниатюра из Deskland;
3. иконка-заглушка GTK.

### 6.1. Запись GIF

В репозитории есть `tools/capture-theme.py`. Он рендерит страницу в
`Gtk.OffscreenWindow` (на экране ничего не появляется), вызывает кадры с
нужными временами и склеивает GIF:

```bash
python3 tools/capture-theme.py prototype/night.html docs/theme-night.gif \
    --frames 30 --size 1280x720 --width 400
```

Требования к странице:

- понимать `?freeze=1` — не запускать `requestAnimationFrame`;
- иметь `window.__renderAt(t)` — нарисовать кадр на момент `t` мс.

Без этих двух хуков запись придётся делать скриншотами окна, а это уже
недетерминированно и требует видимого рабочего стола.

Результат: 30 кадров по 100 мс, 400×225, цикл. Размер — 300–400 КБ.

## 7. Инструменты

| Файл | Что делает |
|---|---|
| `tools/capture-theme.py` | запись GIF-превью через `?freeze=1` + `__renderAt(t)` |
| `tools/test-theme.py` | проверка контракта: `ready`, кадр, реакция на `icons`/`settings`/`pause`, ошибки JS |
| `tools/preview-frame.py` | один кадр с сеткой иконок — посмотреть, как сцена выглядит под иконками |
| `tools/bench-theme.py` | время кадра и вклад каждого эффекта по отдельности |

Проверка новой темы перед коммитом:

```bash
python3 tools/test-theme.py prototype/night.html
```

Вывод:

```text
prototype/night.html
  OK   страница отправила ready
  OK   на странице есть canvas
  OK   кадр не пустой
  OK   есть хук __renderAt/__inject (для превью и тестов)
  OK   иконки влияют на кадр
  OK   нет ошибок JS
  яркость в точке иконки: до 419, после 658
```

`SKIP` печатается для тем без хуков (Beach и Meadow написаны до появления
инструментов) и для WebGL-сцен: их пиксели так не прочитать.

### 7.1. Производительность

`tools/bench-theme.py` меряет, сколько стоит кадр, и сразу показывает, какой
эффект за это отвечает:

```text
prototype/night.html (2560x1440)
  всё как есть         10.8 мс/кадр   (92 fps)
  туман выключен        9.2 мс/кадр   (109 fps)
  сияние выключено      0.3 мс/кадр   (4000 fps)
  ореолы выключены      0.1 мс/кадр   (12000 fps)
  без эффектов          0.1 мс/кадр   (12000 fps)
```

Из этого видно: всё время съедает сияние, остальное — доли миллисекунды.
После этого его и стали кэшировать (см. §9). Без замера правки были бы
наугад.

Живой замер того же на этой машине (сцена на экране): **~50% одного ядра**,
из них примерно поровну `themehost.py` и `WebKitWebProcess`. На паузе —
**0.4% одного ядра**.

## 9. Подводные камни

**Типы параметров.** Самая частая причина «ползунок не действует»: в
`themes.json` `default: 1`, а в `P` — `true`. Страница молча игнорирует
значение.

**Масштаб рендера.** Ограничивайте его. `flat.html` делает
`Math.min(devicePixelRatio, P.quality, 0.75)`, а `meadow.html` долгое время
делал то же без последнего слагаемого — и рисовал в 7 раз больше пикселей при
той же картинке (разбор в [`IMPROVEMENTS.md`](IMPROVEMENTS.md), §1). Сцена —
размытый фон под иконками, детализация выше 0.75 не видна.

**`devicePixelRatio`.** Хост присылает физические пиксели. Если забыть
разделить на `devicePixelRatio`, при масштабе 150% ореолы уедут от иконок.
На Wayland это место дополнительно усложняется — см. `WAYLAND.md`, §4.4.

**Файлы рядом со страницей.** WebKit по умолчанию не отдаёт `file://`
странице соседние `.js` и `.png`. В `themehost.py` это включено
(`set_allow_file_access_from_file_urls`), а в `tools/test-theme.py` —
повторено, иначе проверка покажет ложные ошибки.

**Пауза.** Если на паузе просто «не рисовать», но продолжать планировать
кадры, CPU не падает: `requestAnimationFrame` продолжает будить композитор
30 раз в секунду. Нужно именно **не планировать** следующий кадр.

**Цена эффектов.** Полноэкранное сияние, нарисованное честно каждый кадр, —
это ~10 мс на 2560×1440. Лечится тремя приёмами, все применены в
`night.html`:

1. рисовать в маленький буфер и растягивать (`AURORA_K = 4`) — апскейл сам
   даёт размытие;
2. обновлять буфер не каждый кадр (`AURORA_EVERY = 140` мс) — сияние меняется
   медленно, разницы не видно;
3. не рендерить в физических пикселях (`dpr` ограничен единицей): сцена —
   размытый фон под иконками, лишняя детализация не видна.

**Проверка вживую.** Скриншот рабочего стола часто врёт: если поверх висит
любое окно (даже прозрачное), вы снимаете его, а не иконки. Проверять нужно
так:

```bash
wmctrl -k on                      # показать рабочий стол
sleep 1
gnome-screenshot -f /tmp/desk.png
wmctrl -k off                     # вернуть окна
```

И сравнивать не «на глаз», а по числу пикселей характерного цвета иконки в
левом верхнем углу. Иначе легко получить ложную тревогу «иконки пропали».

**Окно `nemo-desktop` не пустое даже когда кажется.** `xwd` по окну иконок
показывает чёрный кадр — это нормально: Nemo рисует через композитор, и
прямое чтение окна содержимого не даёт. Судить можно только по скриншоту
экрана.

**Кэш превью.** WebKit кэширует файлы по URL; при замене GIF карточка может
показать старую версию. Помогает перезапуск `switcher.py`.

**Лицензия.** Проект целиком под GPL-3.0 (`NOTICE`). Новые темы должны быть
совместимы с GPL-3.0. Имена и логотипы Deskland — товарные знаки, их
использовать нельзя.

**Китайский в интерфейсе.** `themes.json` — копия Deskland, там китайские
`name`, `desc`, `unit`, `options`. В приложении они заменяются русскими из
`switcher.py`. Если забыть `THEME_INFO`, в карточке будет китайский текст.

## 10. Сколько это стоит

| Тип темы | Что внутри | Время |
|---|---|---:|
| Градиент/канвас без привязки к иконкам | ~100–150 строк | 1–3 часа |
| 2D-сцена с ореолами и туманом | canvas 2D, спрайты, пара слоёв | 1–2 дня |
| 2D-сцена с рельефом по иконкам | поле расстояний, сглаживание, переходы | 3–5 дней |
| Полноценная WebGL-сцена как Beach/Meadow | шейдеры, ассеты, физика мелочей | 1–2 недели |

Ночная тема — второй вариант: **~580 строк, один вечер** вместе с превью и
тестами. Именно поэтому она и была сделана: чтобы контракт был не теорией, а
рабочим примером.

Замер на этой машине (2560×1440, 30 fps, сцена активна): **~50% одного ядра**,
то есть примерно **2.5% от всего процессора** (20 потоков). Beach при тех же
условиях — ~65% одного ядра, потому что там WebGL-шейдер на весь экран.

## 11. Можно ли собрать тему «с нуля», без исходников Deskland

Да. Ночная тема это доказывает: она не использует ни одного файла из
`prototype/assets/`, все материалы — градиенты, шум и фигуры, нарисованные
кодом.

Что реально нужно, чтобы собрать новую тему:

| Материал | Обязателен | Где брать |
|---|---|---|
| Идея и палитра | да | подбирается вручную |
| Геометрия сцены | да | код: canvas 2D, SVG или WebGL |
| Текстуры, персонажи | нет | рисуются кодом, либо PNG в `prototype/assets/` |
| Шум/зерно | нет | генерируется функцией (`mulberry32` + синусы) |
| Превью | нет, но принято | `tools/capture-theme.py` |

Ограничение одно: **ассеты должны быть своими или GPL-совместимыми**.
Готовые PNG из Deskland уже в репозитории под GPL-3.0 — их можно
переиспользовать, но нельзя приносить картинки с неясной лицензией.

### 11.1. Как была собрана тема «Ночь» (разбор)

Ночная тема — не пример «на словах», а пройденный путь. Полезно знать, что
именно заняло время.

**Что сделано без единого внешнего файла:**

- небо — линейный градиент + диагональная «млечная» дымка;
- звёзды — детерминированный ГПСЧ (`mulberry32`), ~700 точек, часть мерцает;
- луна — два радиальных градиента плюс три кратера;
- полярное сияние — три ленты, каждая из ~190 вертикальных «лучей» с
  индивидуальной длиной и яркостью; высокочастотная составляющая даёт
  эффект штор;
- туман — 9 копий спрайта-облака, маска по краям, медленный дрейф;
- ореолы иконок — один радиальный спрайт, по одному на иконку;
- метеоры — параметризованный отрезок с градиентом, «жизнь» 0.95 с;
- холмы — две синусоидальные линии с градиентной заливкой.

**Что заняло больше всего времени:** не код, а **подбор вида сияния**. Первые
три подхода дали полосы, «столбики» и шов между спрайтами — на скриншотах это
видно сразу, а в коде выглядит нормально. Помогло то, что каждый вариант
записывался в GIF и сравнивался глазами.

**Что дало основной выигрыш по CPU:** кэш буфера сияния и ограничение `dpr`.
До этого кадр стоил ~12 мс, после — ~2.5 мс (см. §7.1).

**Вывод:** тему среднего уровня можно собрать за один вечер, если есть
инструменты (`capture`, `test`, `bench`, `preview-frame`). Без них цикл
«изменил → посмотрел → замерил» растягивается в разы.

## 12. Порядок действий

1. **Определить уровень** (см. §3): фон, ореолы или рельеф по иконкам.
2. **Написать страницу** по контракту из §2; проверить `?wallpaper=1` вручную.
3. **Добавить хук** `__renderAt(t)` и `?freeze=1` — иначе не будет превью.
4. **Прогнать** `tools/test-theme.py`.
5. **Посмотреть** `tools/preview-frame.py` с сеткой иконок.
6. **Записать** `docs/theme-<id>.gif`.
7. **Зарегистрировать** в `themes.json` и `switcher.py`.
8. **Проверить вживую**: включить, переключить, подвигать иконки, выключить,
   включить снова.
9. **Замерить CPU** активной сцены и паузы; если пауза не падает ниже 5%
   одного ядра — искать, что продолжает планировать кадры.
10. **Обновить** таблицу тем в `README.md`.
